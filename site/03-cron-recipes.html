03 · cron recipes (Linux & Mac)

cron is the Unix alarm clock, and it's three things: crontab -e to edit your alarms, one line per alarm, and man 5 crontab when you confuse the min-hour field. This chapter is the middle one.

Reading a cron line

* * * * *  command to run
│ │ │ │ │
│ │ │ │ └── day of week (0–7, 0 and 7 = Sunday)
│ │ │ └──── month (1–12)
│ │ └────── day of month (1–31)
│ └──────── hour (0–23)
└────────── minute (0–59)
LineReads as
0 7 *every day at 07:00
0 7 1Mondays at 07:00
30 8 1 the 1st of the month at 08:30
0 /4 every 4 hours, on the hour
@rebootonce, when the machine boots (good place to start servers)

Setup, in three steps

Step 1 — the job script. One file, absolute paths throughout:

#!/bin/bash
# jobs/daily-digest.sh
cd "$HOME/scheduled-ai-jobs"
/usr/bin/python3 scripts/morning_digest.py \
  --base-url http://127.0.0.1:11434/v1 \
  --model llama3.2 \
  --notes-file "$HOME/scheduled-ai-jobs/my-notes.md" \
  --out-dir logs
chmod +x jobs/daily-digest.sh   # make it executable, once

Step 2 — test by hand. ./jobs/daily-digest.sh, then read logs/morning-digest.log. cron runs in an almost-empty environment — your login's PATH, language settings, and aliases don't exist there. That's why the script uses absolute paths and doesn't trust python resolving correctly.

Step 3 — schedule it.

crontab -e

then add:

# m  h  dom month dow   command
  0  7  *   *     *    $HOME/scheduled-ai-jobs/jobs/daily-digest.sh

Done — daily 07:00 digest. crontab -l shows what's scheduled; crontab -r deletes it (the retirement plan — know it before you need it). % has special meaning in crontab (new-line); if a command needs a literal percent, escape it as \%.

Where output goes

Cron mails you stdout/stderr of your job. Modern systems don't run a mail daemon, so output silently vanishes. We covered you in another way: the scripts log to logs/*.log — that's your real output. To also keep errors:

0 7 * * *  $HOME/scheduled-ai-jobs/jobs/daily-digest.sh >> $HOME/scheduled-ai-jobs/logs/cron.log 2>&1

Systemd timers (the modern Linux option)

Systemd timers are what new Linux distros would rather you use: they have a proper log (journalctl), run catch-ups for missed runs, and are nameable.

~/.config/systemd/user/daily-digest.service:

[Unit]
Description=Morning AI digest

[Service]
Type=oneshot
WorkingDirectory=%h/scheduled-ai-jobs
ExecStart=/usr/bin/python3 scripts/morning_digest.py --out-dir logs

~/.config/systemd/user/daily-digest.timer:

[Unit]
Description=Run the morning AI digest at 7am

[Timer]
OnCalendar=*-*-* 07:00:00
Persistent=true

[Install]
WantedBy=timers.target
systemctl --user daemon-reload
systemctl --user enable --now daily-digest.timer
systemctl --user list-timers          # see when it fires next
journalctl --user -u daily-digest     # read what happened

Persistent=true = "run if the machine was asleep at the appointed time" — a laptop lifesaver. List before-and-afters: list-timers, journalctl.

For macOS, cron still works exactly as shown; launchd is Apple's native alternative, but cron is friendlier for one-line jobs, so this chapter stays with cron.
