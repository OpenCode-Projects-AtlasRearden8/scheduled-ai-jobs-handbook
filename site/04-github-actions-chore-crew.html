04 · GitHub Actions for small repo chores

Some AI chores don't belong to your computer — they belong to a repo. Drafting a weekly changelog, summarizing the last week of commits, tidying a docs index, reviewing a TODO file for stale items. GitHub Actions runs those on GitHub's clock, in the background, with your machine off.

The catch, up front: on GitHub's own runners, your repo files go wherever the model runs — which is the cloud. If the chore touches private data, use the local-first variant at the bottom of this chapter instead.

.github/workflows/weekly-changelog.yml:

name: Weekly changelog draft
on:
  schedule:
    - cron: "0 14 * * 1"   # Mondays 14:00 UTC — GitHub reads UTC only
  workflow_dispatch:        # "Run workflow" button for testing by hand

permissions:
  contents: read

jobs:
  changelog:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0   # full history; the changelog's raw material

      - name: Collect the week's commits
        run: git log --since="7 days ago" --oneline > last-week.txt

      - name: Ask the model for a draft changelog
        env:
          AI_API_KEY: ${{ secrets.AI_API_KEY }}
          AI_BASE_URL: https://api.openai-compatible-provider.example/v1
          AI_MODEL: gpt-4o-mini
        run: |
          python3 - <<'PY'
          import os, sys
          sys.path.insert(0, ".")
          from scripts.ai_job import call_chat

          notes = open("last-week.txt").read()
          reply = call_chat(
              os.environ["AI_BASE_URL"],
              os.environ["AI_MODEL"],
              [
                  {"role": "system",
                   "content": "Write a weekly changelog in Markdown. Use only the supplied commits. Never invent features."},
                  {"role": "user", "content": notes},
              ],
              timeout=120,
              retries=3,
          )
          open("weekly-changelog-draft.md", "w").write(reply)
          print(reply)
          PY

      - name: Save the draft as an artifact
        uses: actions/upload-artifact@v4
        with:
          name: weekly-changelog-draft
          path: weekly-changelog-draft.md

That reuses scripts/ai_job.py's call_chat() — the same endpoint logic, retries, and timeout behavior you tested locally. One client, everywhere.

The local-first recipe

If the job should touch private data, don't send it to a hosted runner. Run a self-hosted runner on an always-on machine of yours:

and follow the install commands GitHub shows. One download, one install, one service start.

  1. Settings → Actions → Runners → New self-hosted runner on the repo,
  2. Point the job at your own Ollama and set runs-on: self-hosted.
jobs:
  digest:
    runs-on: self-hosted
    steps:
      - uses: actions/checkout@v4
      - run: |
          python3 scripts/morning_digest.py \
            --base-url http://127.0.0.1:11434/v1 \
            --model llama3.2 \
            --notes-file NOTES.md \
            --out-dir logs
      - uses: actions/upload-artifact@v4
        with:
          name: morning-digest
          path: logs/morning-digest*.md

One honest warning: a self-hosted runner executes your repo's code as a full-trust process on that machine. Only attach one to a repo you control, and don't do it to public repos where anyone can open PRs that run code.

When to skip Actions altogether

The job is about your machine's files, the model must be local anyway, or you're the only beings awake at that hour but not on the internet — then Chapter 2 (Task Scheduler) or Chapter 3 (cron) is simply the smaller tool. Actions earn their keep for repo chores because the repo already lives there; don't send local chores on a trip.
